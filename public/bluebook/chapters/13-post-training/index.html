    第13章　模型后训练：何时更新参数¶

    Release Candidate 1

    核心问题：当知识、Prompt、Skill和Harness仍不足时，如何用SFT、RL和蒸馏提升模型能力。

    本章回答的三个问题¶

    1. Mid-training、SFT、RL和蒸馏分别解决什么问题？
    2. 如何从已验证轨迹构建训练数据和奖励？
    3. 如何避免训练指标提升但Agent实际能力下降？

    5分钟速读¶

    • 后训练不是修复所有Agent问题的第一选择；先检查上下文、工具、知识和Harness。
    • Mid-training补领域知识和基础能力，SFT学习示范分布，RL利用可验证奖励探索策略。
    • “SFT记忆、RL泛化”是有用直觉，不是所有任务的定律。
    • 数据、环境和验证器通常比算法名称更决定结果。
    • 训练轨迹必须来自受控环境，工具调用、观察和奖励可复核。
    • 奖励结果同时约束过程，防止模型钻空子。
    • 多轮Agent训练需要处理长轨迹、信用分配、环境稳定性和成本。
    • 训练后必须回到完整Agent系统评估，不只看训练Reward。

    一、先判断是否需要训练¶

    按顺序检查：

    1. 缺少最新或私有事实？用RAG。
    2. 缺少可语言化规程？用Prompt或Skill。
    3. 缺少确定性约束和验证？改Harness。
    4. 工具接口难用？重设计工具。
    5. 模型在充分上下文和良好接口下仍稳定失败，且有足够数据和验证器？考虑训练。

    二、四个阶段¶

    Mid-training¶

    在预训练后继续用领域语料训练，补充知识、语言或长上下文等基础能力。需要防止灾难性遗忘和数据污染。

    SFT¶

    从高质量输入—输出或完整轨迹学习。适合格式、风格、工具调用范式和明确示范。

    RL¶

    模型在环境中采样行动，根据奖励更新策略。适合存在可验证目标、需要探索且示范覆盖不足的任务。

    蒸馏¶

    用强模型或系统产生的高质量示范训练更小模型，以降低延迟和成本。必须验证学生模型是否保留工具和安全行为。

    三、训练数据¶

    一条Agent轨迹至少包含：

    objective: ...
initial_state: ...
messages: ...
tool_schemas: ...
actions: ...
observations: ...
final_state: ...
verifier_results: ...
policy_violations: ...
model_and_environment_versions: ...

    过滤：无效工具结果、环境故障、敏感数据、攻击污染、不可复现状态和错误标签。

    四、SFT¶

    优点：稳定、简单、容易控制格式。局限：倾向模仿训练分布，可能记住表面轨迹而不学会在新环境中调整。

    数据质量原则：

    • 示例覆盖成功和正确拒绝；
    • 工具结果真实；
    • 不保留不必要的冗长推理；
    • 同类任务有多种有效轨迹；
    • 保留验证和终止行为；
    • 去除泄漏测试答案的数据。

    五、RL环境¶

    一个可训练环境需要：

    • 可重置初始状态；
    • 稳定工具和观察；
    • 可验证终态；
    • 副作用隔离；
    • 并发和超时控制；
    • 版本化任务和评分器；
    • 轨迹与成本记录。

    生产系统不应直接作为无保护探索环境。使用模拟器、沙箱或可回滚副本。

    六、奖励设计¶

    结果奖励¶

    任务完成、测试通过、最终状态正确。最可靠，但可能稀疏。

    过程约束¶

    惩罚越权、重复调用、跳过审批、无效格式和超预算。过程约束应可确定性验证。

    模型Judge奖励¶

    用于开放质量，但需校准，容易被策略利用。

    推荐：

    Reward = Verified Outcome
       - Policy Violations
       - Invalid/Unsafe Actions
       - Excessive Cost

    不要用容易优化但偏离业务目标的代理指标。

    七、多轮信用分配¶

    长任务最终失败，错误可能发生在早期检索、工具参数或终止判断。方法包括：

    • 步骤级验证；
    • 关键状态奖励；
    • 失败首错标注；
    • 分阶段课程；
    • 截短轨迹与子任务训练；
    • Verifier辅助信用分配。

    过程奖励必须避免把“看起来合理”的步骤奖励得比真实结果更高。

    八、样本效率¶

    • 从真实失败构建高价值任务；
    • 使用难度分层课程；
    • 复用可验证环境；
    • 蒸馏强策略；
    • 优先训练错误频繁且业务价值高的行为；
    • 对相同轨迹做离线分析，减少昂贵Rollout；
    • 路由不同难度到不同模型。

    九、训练后评估¶

    不仅看Reward，还看：

    • 私有保留任务成功率；
    • 工具选择和参数；
    • 安全和审批遵循；
    • 新旧领域回归；
    • 长任务和失败恢复；
    • 延迟、Token和每成功任务成本；
    • 对Prompt Injection和异常观察的鲁棒性。

    模型参数变化可能使旧Harness假设失效，必须重新执行系统级评估。

    十、常见失败模式¶

    失败 控制
    用训练修复知识时效 RAG优先
    训练脏轨迹 结果验证、脱敏、环境分类
    Reward Hacking 环境状态与过程约束
    只看训练Reward 私有系统级评估
    模型学会跳过审批 政策惩罚和代码硬门
    灾难性遗忘 回归集和混合数据
    训练成本失控 课程、蒸馏、离线复用

    十一、检查清单¶

    • [ ] 已证明外部载体不足。
    • [ ] 训练目标和业务成功一致。
    • [ ] 轨迹来自版本化可验证环境。
    • [ ] 敏感、污染和环境故障数据已过滤。
    • [ ] Reward基于真实结果并约束过程。
    • [ ] 有私有保留集和安全回归集。
    • [ ] 训练后执行完整系统评估。
    • [ ] 模型和Harness可独立回滚。
    • [ ] 成本收益优于外部系统改进。
